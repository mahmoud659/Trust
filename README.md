# TrustCap Prototype

Evidence capture and verification prototype with two independent protection layers:

1. **Cryptographic integrity** — SHA-256 image hashing + ECDSA P-256 digital signatures.
   Proves the image was not changed after it was signed.
2. **AI authenticity** — Estimates whether the image content itself was generated by an AI model.

---

## Architecture

```
┌──────────────────────────────────────────────┐        ┌──────────────────┐
│  Streamlit app  (streamlit run app.py)       │ ─────► │  Resemble Detect │
│                                              │ ◄───── │  /api/v2/detect  │
│  ui/auth.py        ← login gate              │        └──────────────────┘
│  app.py + ui/      ← pages & components      │
│  services/verification_service.py            │
│     manifest · SHA-256 · ECDSA · AI · verdict│
└──────────────────────────────────────────────┘
          ▲
          │ same verification code
┌─────────┴──────────────┐
│  api.py  (OPTIONAL)    │  only if another system needs HTTP access
└────────────────────────┘
```

No FastAPI server is needed. The app runs everything in one process.

> **Prototype note:** signing is simulated by the Streamlit application. In production the
> private key must be protected on the client device and never sent to the verification service.

## Quick start (Windows)

```bash
cd "C:\Users\A store\Desktop\trustcap_lab"
pip install -r requirements.txt
copy .env.example .env        # then put your RESEMBLE_API_KEY in .env
streamlit run app.py
```

Open http://localhost:8501 and sign in with the account configured in `.env`
(`AUTH_EMAIL` + `AUTH_PASSWORD_HASH`).

### Login

- Only a PBKDF2-SHA256 **hash** of the password is stored in `.env`.
- Change the password: `python create_password_hash.py`, then replace `AUTH_PASSWORD_HASH`
  (keep it in single quotes) and restart the app.
- 5 wrong passwords lock that email for 5 minutes (shared across browser tabs).
- Sessions expire after `AUTH_SESSION_MINUTES` (default 60).
- `.streamlit/config.toml` binds the app to `localhost`, so only this computer can open it.

### Optional HTTP API

```bash
pip install -r requirements-api.txt
uvicorn api:app --port 8000
```

The API is **not** protected by the login — keep it on localhost or add API authentication before exposing it.

## Verdict model

`verify_evidence()` (and the optional `/verify`) returns the original fields unchanged (`manifest_valid`, `hash_valid`,
`signature_valid`, `verified`, …) plus:

| Field | Meaning |
|---|---|
| `ai_detection` | `{status, provider, label, score, detection_id, reason, cached}` |
| `trust_verdict` | `TRUSTED` / `REVIEW` / `REJECTED` |
| `trust_reasons` | Human-readable explanation |

| Situation | `verified` | `trust_verdict` |
|---|---|---|
| Integrity failed (any tampering) | false | **REJECTED** (AI check skipped, no API cost) |
| Integrity OK, AI score < `AI_REVIEW_THRESHOLD` (0.50) | true | **TRUSTED** |
| Integrity OK, score between thresholds | true | **REVIEW** |
| Integrity OK, score ≥ `AI_REJECT_THRESHOLD` (0.85) | true | **REJECTED** |
| Integrity OK, AI unavailable / not configured / error | true | **REVIEW** |

AI detection is probabilistic — borderline results go to a human instead of being auto-rejected.
Identical images are cached in memory (by SHA-256), so re-verifying costs one API call.

### Standalone endpoint

`detect_ai_standalone()` / optional `POST /detect-ai` → `{image_sha256, ai_detection}` — used by the **AI detection** page.

## UI pages

- **Capture evidence** — metadata, camera, sealed package (hash / manifest / signature / public key), verify, download ZIP.
- **Evidence inspector** — quick-load the ZIP (or upload each part), verify, then the **Tampering Lab**:

| Tab | What changes | Expected result |
|---|---|---|
| Tamper image | Modified image, manifest unchanged | `hash_valid=false`, REJECTED |
| Tamper manifest | Manifest field edited, signature unchanged | `signature_valid=false`, REJECTED |
| Advanced tampering | Modified image + new hash injected, original signature kept | `hash_valid=true`, `signature_valid=false`, REJECTED |

- **AI detection** — check any uploaded or camera image with Resemble, with score gauge and thresholds.

## Known limitation

Verification accepts the public key supplied with the evidence. An attacker could swap the image, generate
their own key pair, and re-sign the manifest. Before real use, the server should look up the
public key by `key_id` from a trusted registry instead of accepting it from the client.
